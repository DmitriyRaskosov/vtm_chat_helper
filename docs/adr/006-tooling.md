# ADR-006. Инструменты: PHPUnit, Pint, Larastan, без strict_types

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

Код пишется в основном ИИ (Composer) по атомарным задачам. Нужны инструменты, которые дёшево ловят ошибки именно этого класса: несуществующие классы и методы, сравнения, всегда истинные или ложные (аудит §2.1.1–3), стилевой шум в диффах. В `project.mdc` было правило «строгая типизация», но ни в одном файле нет `declare(strict_types=1)`; в `composer.json` разрешён плагин Pest, хотя тесты на PHPUnit.

## Decision

1. **PHPUnit 12 — да, Pest — нет.** 54 теста уже на PHPUnit, переписывание не снижает стоимость поддержки. `pestphp/pest-plugin` убирается из `allow-plugins` (задача 001). Если позже понадобятся arch-тесты, Pest можно добавить: он запускает PHPUnit-классы как есть.
2. **Pint — да**, preset `laravel`, `pint.json` в корне. Разовое форматирование всего кода одной задачей (001), далее `pint --dirty` / `--test` в DoD каждой задачи.
3. **Larastan — да** (dev-зависимость `larastan/larastan`), `phpstan.neon`, level 5 с baseline (задача 002). Baseline — не более 50 записей; каждая запись — либо долг со ссылкой на задачу, либо обоснованное исключение с комментарием. Уровень повышается отдельными задачами после этапа 2.
Baseline политика:
- При внедрении baseline = 185 (фактическое состояние legacy).
- После каждой задачи 009–017 baseline регенерируется через --generate-baseline.
- Целевой размер к концу этапа 1 — ≤50 записей.
- Сжимать baseline вручную (удаляя записи без реального фикса) запрещено.
- После `--generate-baseline` размер baseline **не должен вырастать** относительно значения до задачи; рост = новые находки (регрессия), задача не закрывается (см. `.cursor/rules/task-execution.mdc`).
- Новая находка на грязном коде — либо фиксится в той же задаче, либо
  добавляется в baseline с комментарием в задаче.
4. **`declare(strict_types=1)` — нет.** Директива влияет только на приведение скаляров при вызовах из файла, где она объявлена; сам Laravel её не использует. Вход в проекте — из HTTP-запросов и PDO, и в непокрытых зонах директива превратит тихую деградацию в `TypeError` в рантайме. Реальную строгость дают обязательные типы параметров и возвращаемых значений плюс Larastan. Правило «строгая типизация» означает именно это.
5. **ESLint + eslint-plugin-vue — желательно, но не на этапе 1.** Отдельное решение пользователя (новые npm-зависимости).
6. Не вводим: Rector, Deptrac, CI-матрицу (`docs/ARCHITECTURE.md` §8).

## Consequences

- DoD каждой задачи: `pint --test`, `artisan test`, после задачи 002 — `phpstan analyse` без новых ошибок.
- Первый коммит после задачи 001 — чисто форматирующий, его стоит добавить в `.git-blame-ignore-revs`.
- Ошибки типа `int !== 'npc'` ловятся статически, а не в проде.

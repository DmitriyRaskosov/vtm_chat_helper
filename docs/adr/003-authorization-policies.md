# ADR-003. Авторизация только через Policies

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

Аудит (§2.4): Policy и Gate нет. Используются четыре механизма — middleware `storyteller` (`EnsureStoryteller`), статический `CharacterAccess`, `authorize()` в FormRequest, разрозненные `abort` в контроллерах. Проверки дублируются и противоречат друг другу; членство в хронике не проверяется; игрок получает всех персонажей хроники. На этапе 3 глобальная роль `users.role` заменяется ролью в членстве хроники (ADR-007) — менять это в четырёх механизмах сразу дорого и рискованно.

## Decision

1. Единственное место авторизации — Policies, по одной на модель: `CharacterPolicy`, `ScenePolicy`, `GameSessionPolicy`, `MessagePolicy`, `DiaryEntryPolicy`, `ChroniclePolicy`.
2. Вызов — `->can('ability', 'model')` на маршруте или `Gate::authorize()` / `$this->authorize()` в контроллере. Не в FormRequest и не в сервисах.
3. Удаляются: middleware `EnsureStoryteller`, `CharacterAccess`, все `authorize()` в FormRequest, `abort(403)` в контроллерах (задача 030).
4. Policy получает хронику из модели (`$scene->session->chronicle_id` и т. п.), а не из запроса. На этапах 1–2 роль берётся из `users.role`, на этапе 3 — из членства. Меняется только реализация методов Policy.
5. Матрица доступа «роль × маршрут» покрывается Feature-тестами (задача 030, этап 3 — задача 044).
6. До задачи 030 новые механизмы авторизации не вводятся; точечные исправления (задача 005) используют существующие.

## Consequences

- Переход к multi-chronicle сводится к правке Policies и `CurrentChronicle`.
- Ошибка авторизации — всегда 403 через стандартный механизм Laravel; «не найдено в чужой хронике» на этапе 3 — решение ADR-007.
- Видимость списков (игрок видит не всё) — фильтр в сервисе/запросе по правилу из Policy, а не 403; правило фиксируется в тестах.

# 044 — Матрица доступа: чужая хроника

- **Stage:** 3
- **Status:** todo
- **Depends on:** 038, 039
- **Risk:** med
- **Part:** 4
- **Разрешённые зависимости:** нет

## Goal

Игрок из другой хроники получает отказ на каждом API-маршруте, а просмотр сцены пускает только участника хроники этой сцены.

## Context

- План §«Этап 3», задача 044. ADR-007: матрица «чужая хроника × каждый маршрут» обязательна. В 030c это было Out of scope.
- `player_foreign` в `AccessMatrixFixtures` — другой игрок той же хроники (030c). Не переименовывать и не менять его ожидания. Новая роль — `player_other_chronicle`: свой пользователь, своя хроника, членство player только в ней, к фикстурной хронике не причастен.
- `ScenePolicy::view` сейчас `return true` (комментарий «этап 3», его оставил 030b и сохранил 038). Плоские `GET /scenes/{scene}/context` и `GET /scenes/{scene}/participants` из-за этого открыты кому угодно авторизованному. Здесь: активное членство в хронике сцены → true; иначе `Response::deny('Вы не участник этой хроники.')`. Игрок этой хроники по-прежнему может смотреть сцену (не только рассказчик).
- `GameSessionPolicy::view` тоже `return true`. После 039 `GET .../game-sessions/active` стоит за `ChroniclePolicy::view`, но ability сессии оставить согласованной: активное членство хроники сессии или, если модели нет, хроники `CurrentChronicle`. Иначе дыра останется, если маршрут вынесут из группы.
- `MessagePolicy::create` возвращает true. Коллекция после 039 за группой хроники. Если тест чужой хроники на `POST .../messages` всё же не 403/404 — закрыть проверкой членства в хронике сцены, текст отказа тот же, что у сцены.
- Открытый вопрос ADR-007: 403 или 404. Не переключать то, что уже отдают 036/038/039. Зафиксировать фактический код в матрице. Смена 403↔404 — только если пользователь решил вопрос до старта; иначе не выбирать. Для `ScenePolicy::view` кода отказа раньше не было: это 403 (стандарт Policy).
- Дыра, которую нельзя закрыть в Scope: `markTestSkipped('bug: …')` и строка в отчёте, как в 030c. Не чинить молча файлы вне Scope.
- Правила матрицы — `.cursor/rules/testing.mdc`. Роль `player_other_chronicle` дописать туда, иначе следующее правило соврал бы про состав ролей.

## Scope

- `app/Policies/ScenePolicy.php` — метод `view`
- `app/Policies/GameSessionPolicy.php` — метод `view`
- `app/Policies/MessagePolicy.php` — метод `create`, только если шаг 4 показал дыру
- `tests/Feature/AccessMatrixTest.php`
- `tests/Support/AccessMatrixFixtures.php` — пользователь, вторая хроника, членство
- `.cursor/rules/testing.mdc` — роль в списке матрицы

**Out of scope:**
- смена кода 403/404 на маршрутах, где он уже определён 036–039;
- новые способности сверх `view` / при необходимости `create`;
- фронт;
- `docs/Scope.md` (045).

## Steps

1. До правок выписать, какой код чужой пользователь уже получает на `GET /api/chronicles/{фикстура}` и на одном плоском маршруте сцены. Это базовый код для колонки. Не унифицировать его с новым текстом сцены.
2. Фикстура `player_other_chronicle`: вторая хроника, членство player, нет персонажа и членства в фикстурной хронике.
3. `ScenePolicy::view`: активный участник хроники сцены → true; иначе deny с текстом из Context. Комментарий «этап 3» убрать.
4. Колонка `player_other_chronicle` на каждый маршрут матрицы: ожидается 403 или 404 (не 401 и не 2xx). Страж по-прежнему требует все маршруты `api/`. Ожидание старых ролей не менять, кроме тех строк, где `player_foreign` был `EXPECT_ALLOWED` только потому, что `view` возвращал true на чужую сцену — `player_foreign` той же хроники остаётся allowed на `view` сцены.
5. Прогон. Маршрут, где чужая хроника получает не 403/404, — правка только Policy из Scope. Не хватает Policy — `markTestSkipped('bug: …')` и отчёт, код маршрута не латать в контроллере.
6. Обновить абзац матрицы в `testing.mdc`.

## Definition of Done

- [ ] у каждого маршрута `routes/api.php` есть ожидание `player_other_chronicle`
- [ ] `ScenePolicy::view` не возвращает безусловный `true`
- [ ] игрок той же хроники по-прежнему открывает `GET /scenes/{scene}/context` (не 403)
- [ ] игрок другой хроники на этом URL получает 403
- [ ] `sail pint --test` — чисто
- [ ] `sail php vendor/bin/phpstan analyse` — без новых ошибок; baseline не вырос. В отчёте `baseline: <до> → <после>`
- [ ] `sail artisan test` — зелёные, кроме skipped с `bug:` в отчёте. В отчёте `tests: <до> → <после>`
- [ ] `sail artisan migrate:fresh --seed` — проходит

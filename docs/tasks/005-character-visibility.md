# 005 — Видимость списка персонажей для игрока

- **Stage:** 1
- **Status:** done
- **Depends on:** 001
- **Risk:** med
- **Разрешённые зависимости:** нет

## Goal

`GET` списка персонажей возвращает рассказчику всех активных персонажей хроники, а игроку — только его персонажа и участников активной сцены, которые из неё не вышли.

## Context

- Аудит §2.1.5: в `CharacterSheetController::index` (строки ~117–128) вычисляется `$pcId`, но к запросу не применяется.
- Правило видимости согласовано (открытый вопрос аудита №2).
- ADR-003: до задачи 030 новые механизмы авторизации не вводятся; фильтр — в запросе.
- «Не вышли из сцены» = `scene_participants.is_current` (частичный unique `scene_participants_current_unique`).

## Scope

- `app/Http/Controllers/CharacterSheetController.php` — только метод `index` (и приватный хелпер, если нужен)
- `tests/Feature/CharacterTest.php` или новый `tests/Feature/CharacterVisibilityTest.php`

**Out of scope:**
- форма элемента списка в JSON;
- `show` и другие методы контроллера; перенос логики в сервис (задача 026);
- фронтенд.

## Steps

1. Написать 4 теста (сначала красные там, где поведение неверно):
   - рассказчик видит всех активных персонажей хроники;
   - игрок с персонажем и активной сценой видит своего персонажа и текущих участников активной сцены; не видит вышедших и непричастных;
   - игрок с персонажем без активной сцены видит только своего;
   - игрок без персонажа получает пустой список.
2. Применить фильтр в `index`: для не-рассказчика — `id = $pcId` ИЛИ `id IN (текущие участники активной сцены)`.
3. Активную сцену искать тем же способом, что и сейчас в коде (не вводить новый резолвер — задача 024).

## Definition of Done

- [ ] 4 теста из шага 1 — зелёные
- [ ] форма элементов ответа не изменилась (существующие тесты списка зелёные без правок)
- [ ] `sail artisan test` — зелёные; `sail pint --test` — чисто; phpstan — без новых ошибок
- [ ] ручная проверка: список персонажей во фронте под рассказчиком показывает всех

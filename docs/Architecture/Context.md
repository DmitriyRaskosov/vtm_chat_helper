# Контекст Copilot

Контекст развивается отдельными этапами. Реализованы токенный фундамент, Context Builder и иерархическая память L0/L1/scene/session [[Project/Roadmap]].

## Слои памяти

1. `messages` — полная сырая история и источник истины.
2. Context summaries — immutable производная память с полным provenance по сообщениям и дочерним summaries.
3. Рабочий prompt — бюджетированный набор recent messages, summary RAG и message RAG.

## Область контекста

Базовая область — [[Features/Scenes|сцена]]. Каждое сообщение имеет обязательный `scene_id`; история Copilot уже ограничена активной сценой.

## Оценка токенов

`App\Context\TokenEstimator` использует локальную консервативную оценку:

```text
max(1, ceil(число Unicode-символов / CONTEXT_CHARACTERS_PER_TOKEN))
```

По умолчанию один токен оценивается как 3 Unicode-символа. Результат и версия `unicode-chars-v1-cpt3` кешируются в `messages.token_estimate` и `messages.token_estimator_version`; суффикс фиксирует использованный коэффициент.

Это оценка, а не tokenizer конкретной модели. Версия нужна для воспроизводимости и будущего backfill при смене алгоритма.

## Окно L0

`MessageWindowSelector` выбирает старейший непрерывный хронологический префикс:

- не более 15000 оценочных токенов;
- не более 50 сообщений;
- сообщение никогда не режется;
- сообщение, которое не помещается, начинает следующее окно;
- одиночное сообщение длиннее 15000 токенов образует отдельное `oversized`-окно.

`SummarizeSceneWindowJob` запускается после сообщения. Готовое окно создаётся при 50 сообщениях, токенном переполнении следующего целого сообщения или одиночном oversized-сообщении. Неполный остаток принудительно сворачивается при закрытии сцены.

Job фиксирует окно и курсор под блокировкой, вызывает LLM вне транзакции, затем повторно проверяет курсор и атомарно сохраняет summary. Ошибка LLM не двигает курсор. `source_hash`, ограничения БД и unique job предотвращают дубли.

## Иерархия

- **L0** — целые исходные сообщения; `context_summary_sources.source_type=message`.
- **L1** — пять последовательных L0 по умолчанию; источники имеют тип `summary`.
- **scene_final** — все L1 и не вошедшие в L1 остаточные L0 закрытой сцены.
- **session** — ordered final summaries закрытых сцен. При изменении набора сцен создаётся новая immutable-версия.

Каждый summary хранит `first_message_id`, `last_message_id`, narrative, модель, версию prompt и структурированную metadata: `participants`, `locations`, `key_events`, `facts`, `decisions`, `unresolved_threads`.

Для суммаризации L0 используется отдельный профиль `num_ctx=24576`, `num_predict=3000`: он вмещает источник до 15000 оценочных токенов, инструкции и ответ.

## Context Builder

`App\Context\ContextBuilder` собирает фактический input для Copilot с лимитом 12000 оценочных токенов:

1. обязательный system prompt и запрос рассказчика;
2. самые свежие целые сообщения активной сцены в хронологическом порядке;
3. релевантные summaries до исчерпания бюджета;
4. message RAG до исчерпания бюджета.

Сообщение никогда не режется. Message RAG исключается при совпадении с raw ID. Summary исключается, если его диапазон пересекает raw hot tail или уже включённый summary. Текущий глобальный scope RAG намеренно сохранён; отдельный будущий этап введёт явные профили `active_scene`, `game_session` и `global`.

Результат содержит LLM messages и воспроизводимую metadata: версии builder/prompt/оценщика, бюджет и оценку входа, включённые raw message IDs, summary IDs, RAG chunk/source IDs и количество исключённых источников.

## Окно Ollama

Для `qwen3:8b` приложение передаёт:

- `num_ctx=16384` — общее контекстное окно Ollama;
- `num_predict=3000` — максимум токенов генерации;
- максимум 12000 оценочных токенов входа.

Оставшиеся 1384 токена — запас на шаблон чата и погрешность локальной оценки. `num_ctx` и `num_predict` — runtime options Ollama API; лимит L0 15000 не определяет размер prompt Copilot.

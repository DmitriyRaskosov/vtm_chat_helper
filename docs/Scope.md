# Scope

Живой документ. Обновлять при изменении границ.

## Что такое проект

Чат для VtM V20 с Copilot-помощником рассказчика.
Мастер пишет синопсис → Copilot разворачивает в 3 варианта реплики NPC → мастер отправляет в чат.
NPC ведут долговременный дневник, который подмешивается в контекст.
Проект уже не MVP, скорее Early Access с ограниченным и постоянно дополняющимся функционалом.

**Не в проекте (пока):** полная боёвка по рулбуку, автоматический расчёт механик в LLM, рулбук как справочник, world events. Уже есть: броски кубов, лог боя, чарлисты-картинки, упрощённые **активные состояния** персонажа (см. Characters) — часть полей уходит в промпт Copilot.

## Что работает сейчас (20.10.2026)

### Auth / Game / Chat
- Регистрация, логин, логаут, /user.
- Несколько хроник на инстансе. Членство — `chronicle_members` (роль storyteller или player). Приглашение — ссылка с кодом, без почты: API создания и отзыва есть у рассказчика, на фронте только экран принятия `/invitations/:token`.
- Пикер `/chronicles`: список своих хроник, создание, выбор текущей. Роль в интерфейсе — из членства выбранной хроники.
- Сессии, сцены, участники, контекст сцены.
- Сообщения от мастера, игрока, NPC; **системные** (`is_system`) при входе/выходе участника со сцены (опциональный текст от мастера).
- Редактирование текста сообщения: рассказчик — любое; автор — только среди **последних 10** id сцены (`PATCH /api/messages/{message}`).
- Личные заметки: `user_notes` (по пользователю и `scene_id`), `GET/PUT /api/user-notes`.

### Броски кубов и лог боя
- Отдельно от чата и Copilot: записи в `scene_logs`, **не** попадают в `messages` и **не** входят в контекст LLM.
- API (участник хроники, сцена в scope хроники):
  - `POST /api/chronicles/{chronicle}/scenes/{scene}/dice-rolls` — пул, сложность, тип кубика (d4–d20, по умолчанию d10), опционально `character_id`, скрытый бросок (`is_hidden`, только рассказчик).
  - `GET /api/chronicles/{chronicle}/scenes/{scene}/logs?after_id=` — лента лога; игрок видит только `public`, рассказчик — и `storyteller_only`.
- Правила броска (упрощённый V20 на d10): успех — значение ≥ сложности; каждая **1** снимает один успех; **net** = успехи − единицы; **SUCCESS** при net > 0; **FAILURE** при net ≤ 0 (если не botch); **BOTCH** — ни одного успеха на кубах и хотя бы одна 1.
- UI: кнопка 🎲 в композере, модалка броска; боковая колонка «Лог боя» у всех участников (polling ~3 с); панель рассказчика под логом.

### Copilot
- `POST /api/chronicles/{chronicle}/copilot/drafts` — синопсис → 3 драфта.
- DeepSeek (`deepseek-chat`).
- Промпты вынесены в `resources/prompts/` + `PromptRepository`.
- Контекст: NPC-identity, сцена, **character_state** (запас крови и уровень здоровья с штрафом; временная сила воли в промпт **не** передаётся), лор, storyteller-промпт, recent_messages (реплики `[author] Имя: текст`, системные — `[system] …`), direct_relations, personality, biography, diary, closing.
- Модель учитывает blood pool и ранения при генерации реплик NPC (секция `character_state` в метаданных сборки контекста).
- Anti-anchor, quote discipline, speech act, trait examples, length rules.

### Дневник
- `character_diary_entries` с pgvector HNSW.
- L0 (каждые 15 сообщений или при закрытии), L1 (сводка сцены при close). Системные сообщения **не** попадают в промпт L0 и не создают запись сами по себе; курсор `last_diary_message_id` через них всё равно сдвигается.
- bge-m3 (1024 dim, sim ~0.70 на релевантных парах).
- Retrieval: последняя + top-2 семантики, L1 приоритетнее L0.
- UI: список, открыть, редактировать, удалить, пересоздать.

### Characters
- Создание, чтение, идентичность, дисциплины, биография, traits, место (клан/секта), архив, лист-картинка (sheet); **описание** и **инвентарь** на листе (редактирует рассказчик; инвентарь в API только рассказчику).
- **Активные состояния** (`character_states`): владелец PC и рассказчик правят через `PUT /api/characters/{character}/state` — запас крови (`blood_pool`), временная сила воли (`temporary_willpower`), уровень здоровья 0–7 (`health_level`, Healthy … Incapacitated), тип урона (`health_damage`: bashing / lethal / aggravated); штраф к броскам (`health_penalty`) считается на сервере.
- UI: блок состояний на листе и в боковой панели чата (drawer персонажа); игрок меняет своего PC, рассказчик — любого.
- В Copilot для выбранного NPC в контекст попадают только **blood pool** и **health** (читаемый уровень + penalty); сила воли остаётся на листе для стола, но не подмешивается в LLM.

### World
- `world_entities` — identity для characters/locations; `world_relations` — read-only связи (ADR-002). `WorldRelationKind` — 13 унаследованных значений enum, в коде приложения не используются.

### Canon
- `canon_sects`, `canon_clans`, `canon_clan_sects`, `canon_clan_relations`,
  `canon_disciplines`, `canon_clan_disciplines`, `canon_discipline_powers` (пусто),
  `canon_lore_entries`, `canon_lore_entry_entities`.
- 30 статей лора в `resources/canon/lore/*.md`, импорт `canon:import-lore`.

### Демо-данные
- `DatabaseSeeder` — только канон + `ChronicleSeeder` (хроника «Моя первая хроника» без сцен) + `canon:import-lore`; **не** вызывает `DemoSeeder`. Если есть пользователь `admin`, `ChronicleSeeder` создаёт ему членство storyteller в «Моей первой хронике»; если `admin` нет — первому пользователю по id; если пользователей нет, членство не создаётся.
- `php artisan demo:reset` — сброс данных игры (TRUNCATE) с сохранением канона и пользователей, затем `DemoSeeder`: пользователь `admin` / `admin`, членство storyteller в «Demo Chronicle», «Demo Session», активная сцена «Встреча на пустыре», 5 NPC-участников (Абрахам Леру, Август Сент-Клер, Гидеон Эш, Ильзе Фогель, Порижана) с биографиями и traits; **сообщений в чате не создаёт**.

### Tests
- PHPUnit: ~592 passed (25.10.2026), в т.ч. броски/лог боя, ход сессии, OOC, системные сообщения/дневник, ролевые инструменты.

### Известные ограничения
- Чужая хроника: `GET /api/chronicles/{id}` для не-участника — 404; Policy на коллекции и `ScenePolicy::view` — 403. Единого правила нет.
- Выхода из хроники нет. Что делать с персонажем игрока при `left_at`, не задано.
- Несколько рассказчиков в одной хронике схема позволяет, отдельного запрета и переключателя роли в UI нет.
- Рассказчик одной хроники может быть игроком другой. Переключателя роли нет: роль берётся из членства выбранной хроники.

## Правила

- **Миграции:** только схема. Данные — в сидерах. FK в `Schema::create` той таблицы, что ссылается.
- **Правки:** только активные роуты и их потребители. Замороженное не расширять.
- **Канон vs хроника:** `canon_*` — read-only, сиды. Всё остальное — данные игры.
- **Разное:** Не использовать `DB::table(...)->insert(...)` внутри миграций. Исключение: миграции данных (data migrations), когда нужно перенести существующие строки. В текущем проекте таких нет.

# Scope

Живой документ. Обновлять при изменении границ.

## Что такое проект

Чат для VtM V20 с Copilot-помощником рассказчика.
Мастер пишет синопсис → Copilot разворачивает в 3 варианта реплики NPC → мастер отправляет в чат.
NPC ведут долговременный дневник, который подмешивается в контекст.
Проект уже не MVP, скорее Early Access с ограниченным и постоянно дополняющимся функционалом.

**Не в проекте (пока):** полная боёвка по рулбуку, автоматический расчёт механик в LLM, рулбук как справочник, world events. **Уже есть:** броски и лог боя, **боевая секвенция** (инициатива и ходы), генератор прозы по готовым броскам, интерактивный чарлист и макросы, активные состояния (кровь/здоровье в Copilot).

## Что работает сейчас (10.11.2026)

Краткий срез по модулям. Детали API и UI — в коде, `ARCHITECTURE.md` и спеках `docs/specs/`.

### Хроника, доступ, сцена
- Регистрация, Sanctum, несколько хроник, роли storyteller / player, приглашения по ссылке.
- Сессии, сцены, участники, передача хода (`active_character_id`), игровое время хроники (`in_game_date`).
- Контекст сцены: `situation`, `environment_details`, фото, шаблоны из библиотеки локаций.

### Чат
- Раздельные IC и OOC, отдельный режим Narration для роли Рассказчика; OOC не уходит в Copilot и в порог дневника.
- Сообщения PC / NPC / мастера; системные при входе и выходе со сцены.
- Редактирование: мастер — любое; автор — среди последних 10 сообщений сцены.
- Личные заметки по сцене (`user_notes`).
- Доставка: Laravel Reverb (WebSockets) с fallback на опрос там, где ещё нужен.
- Плавающие панели инструментов: кубы, заметки, чарлист, инвентарь; у мастера — чтение дневника NPC.
- Мастерская `/c/{id}/workshop`: персонажи, локации, дневники, редактор промптов.

### Copilot
- Синопсис → три черновика реплики NPC (DeepSeek).
- Сборка контекста: идентичность NPC, сцена, кровь и здоровье, лор (чанки + keyword RAG), дневник (RAG), биография, связи, последние IC-сообщения.
- Промпты в `resources/prompts/`, редактирование из Мастерской.

### Кубы, лог боя, боевая секвенция
- Броски → `scene_logs`, не в чат и не в LLM-контекст. Упрощённый V20 на d10, воля, скрытые броски мастера.
- Макросы в ЛК; пул из статов интерактивного чарлиста.
- **Боевая секвенция:** старт / финиш, инициатива, раунды и ходы, участники (в т.ч. скрытые), синхронизация по WS; лог и броски могут быть привязаны к `combat_encounter_id`, в UI — фильтр лога по активному бою.
- **Трекер боя** в чате (Combat Tracker).

### Генератор события (проза)
- Уже посчитанные атака и защита → художественное описание на русском; исход решает промпт, не код.
- В промпт: ситуация, окружение, **узлы локации** (общие + семантика/ключевые слова по действию).
- Ответ API — поле `description` (чистый текст); в чат и лог не пишется.

### Локации
- Шаблоны хроники (`chronicle_locations`), применение на сцену.
- **Граф узлов** (`location_nodes`): иерархия объектов окружения для генератора событий и физики сцены.

### Дневник NPC
- L0 по порогу сообщений и при уходе; L1 при закрытии сцены и вокруг боёв.
- **Слоёная память:** несколько L1 на одну сцену (до боя, по итогам боя, хвост после); L0/L1 с `combat_encounter_id`; курсор по `to_message_id` последнего L1.
- Эмбеддинги bge-m3, pgvector; выдача в Copilot: последняя запись + top-2 по смыслу.
- UI: полное управление в Мастерской; в чате у мастера — только чтение.

### Персонажи
- Интерактивный чарлист (сетка статов), биография, traits, дисциплины, описание, архив.
- **Состояния:** кровь, здоровье, временная воля (в Copilot — кровь и здоровье).
- **Инвентарь:** надетое видно в контексте NPC; рюкзак — только если явно раскрыт в игре.
- ЛК игрока: аватары, свои PC (несколько на хронику), биография и traits.

### World и канон
- `world_entities`, `world_relations` (read-only, ADR-002).
- Справочники кланов/сект/дисциплин; ~30 статей лора, импорт `canon:import-lore`, чанкинг под RAG.

### Демо
- `DatabaseSeeder` — канон и пустая «Моя первая хроника».
- `demo:reset` — демо-хроника с 8 NPC на сцене, без сообщений в чате (`admin` / `admin`).

### Тесты
- PHPUnit в Sail (PostgreSQL): **~960** тестов, зелёные (ноябрь 2026). Покрытие: чат, Copilot, дневник, бой, локации, матрица доступа API.

### Известные ограничения
- 403 vs 404 для чужой хроники — не унифицировано.
- Нет выхода из хроники; судьба PC при `left_at` не определена.
- Несколько storyteller в одной хронике и роль «и мастер, и игрок» — без отдельного переключателя в UI.

## Правила

- **Миграции:** только схема. Данные — в сидерах. FK в `Schema::create` той таблицы, что ссылается.
- **Правки:** только активные роуты и их потребители. Замороженное не расширять.
- **Канон vs хроника:** `canon_*` — read-only, сиды. Всё остальное — данные игры.
- **Разное:** Не использовать `DB::table(...)->insert(...)` внутри миграций. Исключение: миграции данных (data migrations), когда нужно перенести существующие строки. В текущем проекте таких нет.

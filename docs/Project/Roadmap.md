## 1. Игровые сессии и сцены: backend — готово

- Добавить `game_sessions`, `scenes`, статусы и связи моделей; затем nullable `messages.scene_id`, backfill всех существующих сообщений в служебную сессию/сцену и отдельным шагом сделать FK обязательным.
- Добавить storyteller-only lifecycle API: создать/активировать/закрыть сцену; чтение активной сессии и сцен. `GET/POST /messages` ограничить выбранной активной сценой, сохранив `after_id`.
- Основные точки: `routes/api.php`, `ChatController`, `Message`, миграции, `tests/Feature/ChatTest.php`.
- Приёмка: две сцены не смешивают сообщения; закрытая сцена read-only; существующие данные не теряются; полный backend suite проходит.

См. [[API/Scenes]], [[API/Messages]].

## 2. Сцены: frontend — готово

- Добавить загрузку активной сессии/сцены, переключение доступной ленты и storyteller UI для создания/закрытия сцен в `frontend/src/views/ChatView.vue`.
- Приёмка: polling и отправка всегда используют текущую сцену; игрок не видит управляющие действия; смена сцены не смешивает ленты.

См. [[Architecture/Frontend]], [[Features/Scenes]].

## 3. Основа Context: токены и бюджет — готово

- Создать слой `app/Context/`: версионируемый `TokenEstimator`, `MessageWindowSelector`, DTO окна и конфигурацию лимитов. Добавить `messages.token_estimate` и версию алгоритма с backfill.
- Unit-тестами закрепить границы: 49/50 сообщений, 14999/15000 токенов, следующее невмещающееся сообщение и одиночное oversized-сообщение.
- На этом этапе поведение Copilot не менялось.
- Embed-модель переведена с `nomic-embed-text` (768-d) на `qwen3-embedding:0.6b` (1024-d): миграция очищает `rag_chunks` и меняет размерность, `rag:reindex-messages` восстанавливает индекс сообщений; lore переиндексируется отдельно.

См. [[Architecture/Context]].

## 4. Context Builder без summaries — готово

- Вынести из `NpcCopilotService` сборку recent history и RAG в `ContextBuilder` с общим входным бюджетом, приоритетами секций и metadata о включённых источниках.
- Сначала обеспечить паритет API: system prompt → запрос рассказчика → hot raw history → RAG. Добавить дедупликацию RAG и recent raw по message ID.
- Зафиксировано: `qwen3:8b` поддерживает 40960 токенов, runtime `num_ctx=16384`, максимальный вход Context Builder — 12000, `num_predict=3000`; оставшиеся 1384 токена — технический запас. Этот бюджет не равен лимиту L0 в 15000 токенов.
- Приёмка: массив `drafts` в `POST /api/copilot/drafts` не меняется, а тесты проверяют состав и бюджет фактического запроса Ollama.

См. [[API/Copilot]].

## 5. Сырые запросы Copilot — готово

- Добавить `copilot_requests`: `scene_id`, storyteller, `npc_name`, исходный prompt, drafts, использованные source IDs/context metadata, модель и версии prompt/builder. При отправке выбранного draft передавать `copilot_request_id` и связывать его с итоговым сообщением.
- Инструкции рассказчика не становятся сообщениями мира и не индексируются как канонические события.
- Приёмка: каждый успешный вызов и выбранный результат трассируются; ответ обратно совместимо расширен полем `copilot_request_id`, массив `drafts` не изменён.

## 6. Хранилище и генерация L0 — готово

- Добавить immutable `context_summaries`, `context_summary_sources` и `scene_context_states` с курсором `last_summarized_message_id`.
- После сохранения сообщения проверять старейший непрерывный непокрытый диапазон сцены. При достижении 50 сообщений либо когда следующее целое сообщение не помещается в 15000 токенов, ставить `SummarizeSceneWindowJob`.
- Job фиксирует окно и курсор под транзакционной блокировкой, вызывает `qwen3:8b` вне транзакции, затем повторно проверяет курсор, сохраняет L0 и атомарно двигает состояние. `source_hash`, unique constraints и `ShouldBeUnique` делают повторный запуск безопасным.
- Для L0 до 15000 токенов используется отдельное окно суммаризации `num_ctx=24576` и `num_predict=3000`; Copilot сохраняет собственный профиль 16384/12000/3000.
- Приёмка: сообщения не режутся и не удаляются; параллельные/повторные jobs не создают дублей; сбой Ollama не двигает курсор.

## 7. Подключение L0 к Context Builder — готово

- Добавить summary-секцию: релевантные summaries + raw hot tail активной сцены + непокрытые сообщения. В prompt передавать только бюджетированный набор, а не все summaries; после пункта 8 тот же механизм принимает L1/final/session.
- Добавить `summary` в `RagSourceType`, индексировать summaries в `RagIndexer`. Scope retrieval на этом этапе намеренно оставлен без изменений.
- Приёмка: Copilot использует старый контекст через L0, последние сообщения остаются дословными, а нерелевантные дубли не попадают в prompt.

См. [[API/RAG]].

## 8. Иерархия L1 и финализация — готово

- Объединять последовательные L0 в L1 пакетами настраиваемого размера; хранить связи дочерних summaries. При закрытии сцены сворачивать остаток, создавать `final scene summary`, затем новую immutable-версию `session summary`.
- Структура summary: narrative text плюс metadata (`participants`, `locations`, `key_events`, `facts`, `decisions`, `unresolved_threads`).
- Приёмка: сцена на 1000+ сообщений даёт несколько L0/L1; provenance полностью восстанавливается; закрытие сцены не блокирует доступ к raw history.

## 9. Retrieval и tools — готово

- Ввести `RetrievalOrchestrator` и оформить `search_messages`, `get_message_range`, `search_summaries` как внутренние типизированные PHP tools. Подключить ограниченный tool-call loop с лимитом итераций и результатов.
- Lore/NPC/relationship tools оставлены расширениями того же registry и в этот пункт не входят.
- Приёмка: tools строго scoped по сессии/сцене, имеют лимиты, не возвращают всю историю и покрыты fake-LLM тестами.

См. [[Architecture/Retrieval]].

## 10. Сжатая память промптов рассказчика — готово

- На базе `copilot_requests` построить отдельные rolling summaries намерений рассказчика. Хранить их отдельно от событий мира и подключать в Context Builder как низкоприоритетную секцию.
- Приёмка: намерения помогают последовательности Copilot, но никогда не попадают в world summary и не выдаются игрокам.

## 11. Scope-профили RAG — к работе

- Убрать неявный глобальный поиск и ввести явный scope в `RagSearcher`/retrieval: `active_scene`, `game_session` и, только для осознанных cross-session сценариев, `global`.
- Разрешить разным потребителям выбирать разные профили: Copilot может использовать raw текущей сцены и summaries текущей сессии, storyteller search — выбранную сцену/сессию, будущий lore retrieval — глобальный доменный слой.
- Для `game_session` учитывать приоритет активной сцены, но не смешивать другие игровые сессии. Решить, нужен ли fallback от `active_scene` к `game_session`, и сделать его явным и тестируемым.
- Приёмка: каждый retrieval-вызов указывает scope; тесты доказывают изоляцию сессий и корректный приоритет сцены; глобальный профиль нельзя получить случайно.

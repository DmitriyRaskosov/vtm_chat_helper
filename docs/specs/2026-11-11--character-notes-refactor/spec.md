# Spec: Рефакторинг заметок (Character Notes)

**Status:** Completed
**Date:** 2026-11-11

## 1. Контекст и Цель

Сейчас личные заметки пользователей (`user_notes`) привязаны к сцене (`scene_id`). Это создает неудобства: при переходе на новую сцену заметки пропадают из интерфейса, и игрокам приходится вести их во внешних файлах.

Цель — отвязать заметки от сцен и привязать их к конкретному персонажу в рамках хроники. Заметки должны быть строго личными (каждый пользователь видит только свои записи) и сохраняться между сценами. Интерфейс для работы с заметками должен быть доступен как в чате (для текущего персонажа), так и в Личном кабинете (на листе персонажа).

## 2. User Stories

*   **US-1:** Как игрок, я хочу вести заметки за своего персонажа, чтобы они сохранялись при смене сцен.
*   **US-2:** Как рассказчик, я хочу вести личные заметки о любом NPC на сцене, чтобы не забывать их секреты.
*   **US-3:** Как пользователь, я хочу видеть свои заметки как в плавающем окне в чате, так и на странице персонажа в Личном кабинете.
*   **US-4:** Как система, я хочу, чтобы заметки были строго конфиденциальными: никто, кроме автора, не может их прочитать или изменить.

## 3. Acceptance Criteria (EARS)

*   **AC-1 (Модель данных):** THE system SHALL хранить заметки с привязкой к пользователю (автору), персонажу и хронике. Привязка к сцене SHALL быть удалена.
*   **AC-2 (Права доступа):** IF пользователь запрашивает заметки, THE system SHALL возвращать только те, где `user_id` совпадает с текущим пользователем.
*   **AC-3 (Права на создание):** 
    *   IF пользователь является игроком, THE system SHALL разрешать ему писать заметки только к своим PC.
    *   IF пользователь является рассказчиком, THE system SHALL разрешать ему писать заметки к любым NPC и своим PC в текущей хронике.
*   **AC-4 (Сохранение):** WHEN пользователь сохраняет заметку, THE system SHALL сохранять текст в привязке к текущему персонажу и хронике (upsert).
*   **AC-5 (UI Чат):** THE system SHALL отображать кнопку заметок в чате, открывающую заметки для выбранного в данный момент персонажа.
*   **AC-6 (UI ЛК):** THE system SHALL отображать блок заметок на странице листа персонажа (CharacterSheetView), доступный только владельцу персонажа (или рассказчику для NPC).
*   **AC-7 (Миграция):** THE system SHALL очистить существующие заметки при применении миграции (truncate).

## 4. Out of Scope

*   Общие заметки (видимые всем участникам хроники).
*   Заметки за пределами хроники (глобальные заметки игрока).
*   Rich-text (форматирование) в заметках — только чистый текст.

## Post-Implementation Notes

- Миграция `2026_11_11_000001_recreate_user_notes_table` выполняет `Schema::dropIfExists('user_notes')` и создаёт таблицу заново. Старые заметки, привязанные к сценам, не переносятся (данные тестовые, потеря согласована).
- API: `GET/PUT /api/chronicles/{chronicle}/characters/{character}/note`, тело `{ "body": "..." }`. Старые маршруты `/api/user-notes` удалены.
- В UI заметки привязаны к ID персонажа: в чате `notesCharacterId` в `ChatView` (игрок — PC в селекторе, рассказчик — «Писать от лица»), тот же паттерн, что у инвентаря; composable `useUserNotes` загружает и сохраняет по `chronicleId` + `characterId`.
- Для вложенного маршрута с `scopeBindings` добавлена связь `Chronicle::characters()` — без неё implicit binding падал с 500.
- Покрытие прав: `tests/Feature/UserNoteTest.php`, строки в `AccessMatrixTest` для `characters.note.show|update`.

# Spec: Фикс Retrieval для Графа Локаций

**Status:** Completed
**Date:** 2026-11-05

## 1. Контекст и Цель
Поиск по смыслу плохо находит короткие названия объектов локации. Генератор событий должен находить объекты и по смыслу описания действия, и по словам в названии, и по-прежнему опираться на общий каркас места. Новых полей ввода для этого нет.

## 2. User Stories
*   **US-1:** Как рассказчик, я хочу описывать действие обычным текстом, чтобы генератор сам нашёл подходящие объекты локации.
*   **US-2:** Как рассказчик, я хочу, чтобы короткие названия находились по словам, а не только по смысловой близости, чтобы генератор не пропускал очевидные предметы.
*   **US-3:** Как рассказчик, я хочу, чтобы без объектов в локации генератор по-прежнему использовал текст описания окружения.

## 3. Acceptance Criteria (EARS)
*   **AC-1:** WHEN рассказчик описывает действие для генератора, THE system SHALL брать этот текст из уже существующего поля описания действия. Новых полей ввода нет.
*   **AC-2:** WHEN генератор ищет объекты локации, THE system SHALL учитывать и смысловую близость к описанию действия, и совпадение слов этого описания с именами объектов.
*   **AC-3:** WHEN один и тот же объект найден обоими способами, THE system SHALL включить его в промпт один раз.
*   **AC-4:** WHEN у локации есть дерево объектов, THE system SHALL по-прежнему добавлять в промпт общий каркас: корневые объекты и их прямые части.
*   **AC-5:** IF подходящих объектов нет ни в общем каркасе, ни среди найденных по действию, THE system SHALL использовать исходный текст описания окружения.

## 4. Out of Scope
*   Новое поле ввода специально для поиска объектов.
*   Ручная настройка порога сходства рассказчиком.

## 5. Post-Implementation Notes
Поиск объектов совмещает смысловую близость и совпадение слов в названии. Общий каркас локации по-прежнему попадает в промпт. Если отдельных подходящих объектов нет, используются общий каркас и исходный текст окружения.

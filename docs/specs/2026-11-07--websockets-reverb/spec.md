# Spec: WebSockets (Мгновенная доставка данных)

**Status:** Completed
**Date:** 2026-11-07

## 1. Контекст и Цель
Сейчас приложение использует polling (опрос каждые 3 секунды), что создает задержку и лишнюю нагрузку. 
Цель — внедрить WebSockets для мгновенной доставки сообщений, обновления статов, индикатора «Печатает...» и лога боя. При потере соединения система автоматически переключается на резервный polling, не теряя данные.

## 2. User Stories
*   **US-1:** Как игрок, я хочу получать новые сообщения и броски кубов мгновенно, чтобы не ждать 3 секунды.
*   **US-2:** Как игрок, я хочу видеть, когда другие участники набирают текст, чтобы понимать, что диалог продолжается.
*   **US-3:** Как рассказчик или игрок, я хочу, чтобы изменения статов (кровь, здоровье) мгновенно отображались у всех, у кого открыт этот лист.
*   **US-4:** Как пользователь, я хочу, чтобы при обрыве связи чат продолжал работать (в режиме polling), и не терял сообщения.

## 3. Acceptance Criteria (EARS)
*   **AC-1 (Подключение):** WHEN клиент открывает сцену, THE system SHALL устанавливать WebSocket-соединение. Если соединение не установлено за 5 секунд, THE system SHALL переключаться в режим polling.
*   **AC-2 (Сообщения):** WHEN пользователь отправляет сообщение, THE system SHALL доставлять его всем участникам сцены без задержки polling (в рамках одного WS-события).
*   **AC-3 (Статы):** WHEN участник меняет статы персонажа, THE system SHALL транслировать обновление всем, у кого открыта текущая сцена (и отфильтровывать на клиенте по ID персонажа).
*   **AC-4 (Печатает):** WHEN пользователь набирает текст, THE system SHALL показывать индикатор «Печатает...» остальным. Индикатор гаснет, если ввод прекратился на 3 секунды (троттлинг: не чаще 1 события в 2 секунды).
*   **AC-5 (Лог боя):** WHEN происходит бросок кубов, THE system SHALL мгновенно добавлять его в Лог боя у всех участников сцены.
*   **AC-6 (Смена локации):** WHEN рассказчик меняет локацию, THE system SHALL мгновенно обновлять баннер локации у всех игроков.
*   **AC-7 (Fallback и дедупликация):** IF WebSocket падает > 5 секунд, THE system SHALL включать polling. WHEN WebSocket восстанавливается, THE system SHALL отключать polling и синхронизировать пропущенные данные (по `after_id`), исключая дубликаты.
*   **AC-8 (Безопасность):** THE system SHALL разрешать подписку на каналы сцены только ее участникам.

## 4. Out of Scope
*   WebRTC (голосовой чат).
*   Трансляция позиций фигурок на карте.

## 5. Post-Implementation Notes

Внедрены WebSockets (Laravel Reverb) для мгновенной доставки сообщений, статов персонажа (канал сцены, фильтр по `character_id` на клиенте), лога боя и смены контекста/локации. Docker-сервис `reverb`, Echo на фронте; авторизация приватного канала через `POST /broadcasting/auth` (инстанс `apiRoot`, не `/api`).

Реализован индикатор «Печатает...»: `POST /api/scenes/{scene}/typing` → `UserTyping`, троттлинг запроса раз в 2 с, гашение индикатора у получателей через 3 с.

Настроен fallback: `useConnectionStatus` слушает `state_change` Echo; при недоступности WS дольше 5 с включается резервный polling и баннер «Соединение нестабильно». При восстановлении polling отключается, сообщения и лог догоняются по `lastId` / `after_id`; дубликаты отсекаются по `id > lastId`.

Фронтенд-тесты: `npm test` (`connectionStatusLogic.test.js`) проверяют таймеры lost/restored. Backend: `WebSocketBroadcastTest`, Access Matrix для typing.

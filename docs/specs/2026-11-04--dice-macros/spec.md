# Spec: Макросы кубиков (Dice Macros)

Status: Completed

## 1. Контекст и Цель
Сейчас игроки и рассказчик каждый раз вручную вводят пул, сложность и тип кубика в окно броска. Это замедляет игру. 
Цель — создать систему макросов (пресетов) для быстрого броска. Макросы привязываются к пользователю (игроку/рассказчику) и управляются в Личном кабинете. В будущем макросы будут автоматически вытягивать значения статов из интерактивного чарлиста.

## 2. User Stories
*   **US-1:** Как игрок, я хочу создавать макросы для своих частых действий (например, «Атака шпагой») в Личном кабинете, чтобы не вводить параметры каждый раз.
*   **US-2:** Как рассказчик, я хочу создавать макросы для NPC (например, «Стандартная атака»), чтобы быстро бросать за них.
*   **US-3:** Как пользователь, я хочу выбирать сохраненный макрос прямо в окне броска кубиков, чтобы мгновенно заполнить форму.

## 3. Acceptance Criteria (EARS)
*   **AC-1 (БД):** THE system SHALL создать таблицу `dice_macros` (id, user_id, name, pool, difficulty, dice_type, use_willpower, stats).
    *   Поле `stats` — jsonb (массив строк). Позволяет хранить 1, 2 или более статов (например, `["dexterity", "athletics"]`). Может быть пустым (`[]`), если бросок ручной.
*   **AC-2 (Права):** WHEN пользователь запрашивает список макросов, THE system SHALL возвращать только его макросы (по user_id).
*   **AC-3 (UI - ЛК):** В Личном кабинете (`ProfileView.vue`) появляется секция «Макросы кубиков» с возможностью создавать, редактировать и удалять макросы.
*   **AC-4 (UI - Кубы):** В окне броска кубиков (`DiceRoller.vue`) появляется выпадающий список «Макросы». При выборе макроса поля (Пул, Сложность, Тип куба, Трата Воли) заполняются значениями из макроса. Пользователь может их отредактировать перед броском.
*   **AC-5 (Будущее):** Архитектура должна позволять в будущем заменить ручной ввод `pool` на автоматический расчет из массива `stats` (при наличии интерактивного чарлиста).

## 4. Out of Scope
*   Автоматический расчет пула из статов (в текущей итерации пул вводится вручную).
*   Автоматическая проверка наличия трат временной воли.
*   Автоматическое опциональное (!) правило V20 «если один стат равен 0, сложность повышается на 1».

## 5. Technical Context
*   **Маршруты:** `GET/POST /api/dice-macros`, `PATCH/DELETE /api/dice-macros/{id}`.
*   **Модель:** `DiceMacro` (fillable: user_id, name, pool, difficulty, dice_type, use_willpower, stats; casts: stats => 'array', use_willpower => 'boolean').
*   **UI:** Форма в ЛК (поле «Статы» как текст через запятую), выпадающий список в `DiceRoller.vue`.

## 6. Post-Implementation Notes

Макросы привязаны к пользователю. Игрок и рассказчик заводят их в личном кабинете (у рассказчика секция видна, хотя списка персонажей у него нет) и подставляют в окно броска. Выбор макроса заполняет пул, сложность, тип куба и трату Воли; эти поля остаются обычной формой, их можно поменять перед броском. Чужие макросы не отдаются в списке и не правятся: `DiceMacroPolicy` отвечает 403.

Поле `stats` — `jsonb`, в модели каст `array`. В API это JSON-массив строк (`["dexterity", "athletics"]`) или `[]`, если бросок ручной. В кабинете строка через запятую режется в этот массив перед сохранением. Пул по-прежнему вводится руками. Имена статов только хранятся: расчёт пула из интерактивного чарлиста, проверка временной Воли и правило «стат 0 повышает сложность» не делались.

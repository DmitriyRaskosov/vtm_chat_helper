# Spec: Макросы кубиков (Dice Macros)

**Status:** Completed
**Date:** 2026-11-04

## 1. Контекст и Цель
Игроки и рассказчик каждый раз заново вводят пул, сложность и тип кубика. Макросы — сохранённые броски пользователя. Ими управляют в личном кабинете и подставляют в окно броска. Позже пул можно будет считать по листу; в этой фиче число пула задаётся руками, а список статов только запоминается.

## 2. User Stories
*   **US-1:** Как игрок, я хочу сохранять частые броски в личном кабинете, чтобы не вводить параметры каждый раз.
*   **US-2:** Как рассказчик, я хочу сохранять броски для NPC, чтобы быстро кидать за них.
*   **US-3:** Как пользователь, я хочу выбрать сохранённый макрос в окне броска, чтобы поля заполнились сами, и поправить их перед броском.

## 3. Acceptance Criteria (EARS)
*   **AC-1:** WHEN пользователь сохраняет макрос, THE system SHALL запомнить название, пул, сложность, тип кубика, трату Воли и список статов. Список статов может быть пустым, если бросок задаётся только числами.
*   **AC-2:** WHEN пользователь открывает макросы, THE system SHALL показать только его макросы. Чужой макрос нельзя просмотреть или изменить.
*   **AC-3:** WHEN пользователь открывает личный кабинет, THE system SHALL показать раздел «Макросы кубиков», где макрос можно создать, изменить и удалить.
*   **AC-4:** WHEN пользователь выбирает макрос в окне броска, THE system SHALL заполнить пул, сложность, тип кубика и трату Воли. Эти значения можно изменить перед броском.
*   **AC-5:** WHEN макрос хранит список статов, THE system SHALL сохранять его отдельно от введённого пула и не пересчитывать пул по листу в этой фиче.

## 4. Out of Scope
*   Автоматический расчёт пула из статов листа. Пул вводится вручную.
*   Автоматическая проверка, что временная Воля ещё есть.
*   Правило «если один стат равен 0, сложность повышается на 1».

## 5. Post-Implementation Notes

Макросы привязаны к пользователю. Игрок и рассказчик заводят их в личном кабинете (у рассказчика секция видна, хотя списка персонажей у него нет) и подставляют в окно броска. Выбор макроса заполняет пул, сложность, тип куба и трату Воли; эти поля остаются обычной формой, их можно поменять перед броском. Чужие макросы не отдаются в списке и не правятся: `DiceMacroPolicy` отвечает 403.

Поле `stats` — `jsonb`, в модели каст `array`. В API это JSON-массив строк (`["dexterity", "athletics"]`) или `[]`, если бросок ручной. В кабинете строка через запятую режется в этот массив перед сохранением. Пул по-прежнему вводится руками. Имена статов только хранятся: расчёт пула из интерактивного чарлиста, проверка временной Воли и правило «стат 0 повышает сложность» не делались.

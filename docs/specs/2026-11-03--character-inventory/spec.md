# Spec: Инвентарь персонажа

Status: Completed

## 1. Контекст и Цель
Игрокам и рассказчикам нужен инструмент для учета вещей персонажа. Простое текстовое поле неудобно, а также возникает риск дублирования предметов между описанием внешности (traits) и инвентарем. 
Цель — создать структурированный инвентарь, разделенный на «Экипированные» вещи (часть внешности) и «В рюкзаке» (скрытые), с передачей этих данных в промпт LLM.

## 2. User Stories
*   **US-1:** Как игрок, я хочу вести список вещей своего персонажа, разделяя их на те, что видны всем, и те, что спрятаны.
*   **US-2:** Как рассказчик, я хочу видеть инвентарь NPC, чтобы понимать, чем они располагают.
*   **US-3:** Как система (LLM), я хочу получать четкий список экипировки, чтобы не путать «трость в руке» с «второй тростью в рюкзаке».

## 3. Acceptance Criteria (EARS)
*   **AC-1 (БД):** THE system SHALL создать таблицу `character_items` (id, character_id, name, quantity, description, is_equipped).
*   **AC-2 (API):** THE system SHALL предоставить CRUD-эндпоинты для управления вещами персонажа (`/api/characters/{id}/items`).
*   **AC-3 (Права):** Владелец персонажа и рассказчик могут редактировать инвентарь. Остальные — только просматривать (если есть доступ к листу).
*   **AC-4 (UI):** В чате рядом с Заметками (`📝`) появляется кнопка `🎒 Инвентарь`. По клику открывается окно с двумя списками: «Экипировано» и «В рюкзаке».
*   **AC-5 (Промпт):** Инвентарь попадает в контекст Copilot через новый `InventoryProvider`. Для экипированных вещей указывается пометка, что они являются частью внешности.

## 4. Out of Scope
*   **Вес и слоты:** Не считаем вес предметов и не ограничиваем количество слотов (руки/голова).
*   **Механика:** Предметы не дают бонусов к кубам и не меняют статы автоматически (это работа рассказчика).

## 5. Technical Context
*   **БД:** `character_items` (character_id FK, name string, quantity int default 1, description text nullable, is_equipped boolean default false).
*   **Frontend:** Новый composable `useCharacterInventory.js`. Модалка `InventoryPanel.vue`.
*   **Context:** Создать `app/Context/Providers/InventoryProvider.php`. Добавить в `ContextAssembler`.

## 6. Post-Implementation Notes

Сделано: таблица `character_items`, CRUD `/api/characters/{id}/items`, право `manageItems` (владелец PC и рассказчик), плавающее окно «Инвентарь» в чате и секция `inventory` в контексте Copilot (лимит 200 токенов).

Свои надетые вещи говорящего персонажа выводятся как `Your Equipped`. Экипировка остальных текущих участников сцены (`is_current`) дописывается блоком `Others' Equipped` и подгружается одним запросом через `with('character.items')`, только строки с `is_equipped`. Содержимое рюкзака — и своё, и чужое — в промпт не попадает: скрытые вещи остаются в интерфейсе и в базе, но Copilot их не видит, пока рассказчик сам не опишет, что рюкзак открыли. Если нет ни своей экипировки, ни чужой, секция `omitted`. Если текст не влезает в бюджет, с конца снимаются строки чужой экипировки, затем своя.

Правила инвентаря добавлены в `resources/prompts/copilot/reply.system.md`. Версия промпта: `npc-drafts-v10` после появления секции, `npc-drafts-v11` после имён `Your Equipped` / `Others' Equipped`, `npc-drafts-v12` после того, как рюкзак убрали из контекста.

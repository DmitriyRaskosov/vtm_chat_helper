# Spec: Глобальная библиотека персонажей (Этап 7)

**Status:** Completed
**Date:** 2026-11-13

## 1. Контекст и Цель

Сейчас персонажи (characters) жестко привязаны к конкретной хронике (chronicle_id). Если игрок хочет начать новую хронику или перенести своего персонажа в другой мир, ему приходится создавать его заново с нуля.

Цель — создать «Глобальную библиотеку персонажей» (Шаблоны). Игроки и рассказчики смогут сохранять снимок персонажа (со всеми статами, биографией, дисциплинами и инвентарем) в личную библиотеку. При добавлении такого шаблона в конкретную хронику создается его независимая копия. Изменения в копии (получение урона, новые предметы) не влияют на исходный шаблон в библиотеке.

## 2. User Stories

*   **US-1:** Как игрок, я хочу сохранить своего персонажа в глобальную библиотеку, чтобы не создавать его заново для новой хроники.
*   **US-2:** Как пользователь, я хочу видеть список своих шаблонов в ЛК отдельно от персонажей, участвующих в хрониках.
*   **US-3:** Как пользователь, я хочу добавить шаблон из библиотеки в текущую хронику одной кнопкой, получив полную копию (статы, био, дисциплины, инвентарь).
*   **US-4:** Как система, я хочу, чтобы редактирование персонажа в хронике не меняло его шаблон в библиотеке.
*   **US-5:** Как система, я хочу синхронизировать дисциплины при клонировании, чтобы сетка чарлиста и данные для Копилота не расходились.

## 3. Acceptance Criteria (EARS)

*   **AC-1 (Схема данных):** THE system SHALL создать таблицы для библиотеки, зеркально отражающие структуру персонажа (основная сущность, биография, дисциплины, силы, предметы).
*   **AC-2 (Сохранение в библиотеку):** WHEN пользователь сохраняет персонажа как шаблон, THE system SHALL копировать все данные персонажа (включая JSON-поля, дочерние таблицы предметов и дисциплин) в новые таблицы библиотеки.
*   **AC-3 (Список шаблонов):** THE system SHALL отображать вкладку «Библиотека» в ЛК со списком сохраненных шаблонов.
*   **AC-4 (Импорт в хронику):** WHEN пользователь добавляет шаблон в хронику, THE system SHALL создавать нового персонажа и все связанные дочерние записи (био, предметы, дисциплины, world_entity).
*   **AC-5 (Синхронизация дисциплин):** WHEN происходит импорт, THE system SHALL генерировать JSON-поле `stats.disciplines` на основе созданных реляционных записей `character_disciplines`, чтобы сетка чарлиста соответствовала данным для LLM.
*   **AC-6 (Независимость):** Изменение статов или инвентаря у персонажа в хронике SHALL NOT изменять данные в библиотеке.
*   **AC-7 (Права):** Пользователь может управлять только своими шаблонами в библиотеке.

## 4. Out of Scope

*   Автоматическое обновление шаблона в библиотеке при изменении персонажа в хронике (только ручное пересохранение).
*   Обмен шаблонами между разными пользователями (библиотека строго личная).

## 5. Post-Implementation Notes

Реализована полная копия дочерних таблиц при сохранении в библиотеку и при импорте в хронику: биография, предметы (`character_items` → `library_character_items`), дисциплины и силы (`character_disciplines` / `character_powers` и зеркальные `library_*`), плюс JSON-поля `stats` и `sheet_data`.

При импорте поле `stats.disciplines` пересобирается из созданных записей `character_disciplines` (slug → dotTrack через `CharacterStatsService`), чтобы сетка чарлиста совпадала с данными для Copilot.

Импорт: `POST /api/chronicles/{chronicle}/characters/import` с `library_character_id`. Личная библиотека: вкладка «Библиотека» в `/profile`, API `GET/POST/DELETE /api/library-characters`.

Аватары и `avatar_path` в шаблон не копируются — на вкладке библиотеки показывается плейсхолдер «Нет аватара».

Автоматизировано: `LibraryCharacterTest`, `LibraryCharacterApiTest`, маршруты в `AccessMatrixTest`. Полный `php artisan test` (1008 passed, 1 skipped), Pint, PHPStan, `npm run build` — зелёные.

# Spec: {Название фичи}

## 1. Контекст и Цель
*Кратко: зачем мы это делаем? Какую проблему решаем?*
**Пример:** Игроки хотят визуализировать своих персонажей. Сейчас в чате только текст.

## 2. User Stories (Пользовательские истории)
*Формат: Как [роль], я хочу [действие], чтобы [ценность].*
*   **US-1:** Как игрок, я хочу загрузить картинку-аватар для своего персонажа, чтобы другие видели, как он выглядит.
*   **US-2:** Как рассказчик, я хочу видеть аватар игрока в списке участников сцены.

## 3. Acceptance Criteria (Критерии приемки)
*Формат EARS (When/While/If -> The system shall). Это то, что будет проверять тестировщик (или ИИ).*
*   **AC-1:** WHEN пользователь загружает файл размером более 2 МБ, THE system SHALL вернуть ошибку 422 с понятным текстом.
*   **AC-2:** WHEN аватар успешно загружен, THE system SHALL отображать его в правой панели (сайдбаре) рядом с именем персонажа.
*   **AC-3:** WHEN аватар не загружен, THE system SHALL отображать дефолтную заглушку (инициалы или силуэт).

## 4. Out of Scope (Чего мы НЕ делаем в этой фиче)
*   Анимированные GIF-аватары.
*   Кроппинг (обрезка) изображения прямо в браузере.

## 5. Technical Context (Технический контекст)
*   Где хранить файлы: `storage/app/public/avatars`.
*   Какие таблицы затрагиваем: `characters` (добавить `avatar_path`).

# Spec: Граф локаций (Location Nodes)

## 1. Контекст и Цель
Текстовое описание локации (`environment_details`) слишком велико для промпта Генератора Событий и не структурировано. 
Цель — внедрить структурированное дерево объектов (GraphRAG). Узлы принадлежат **шаблону локации** (`chronicle_locations`), а не сцене. Мастер парсит текст через LLM, дерево сохраняется. Генератор Событий использует гибридный поиск (General + Specific) для физики.

## 2. Acceptance Criteria (EARS)
*   **AC-1 (БД):** THE system SHALL создать `location_nodes` (id, chronicle_location_id, parent_id, name, description, embedding).
*   **AC-2 (Парсинг):** WHEN мастер нажимает «Разобрать на объекты», THE system SHALL отправить текст в LLM (JSON Mode), получить дерево и сохранить его (с использованием `embedBatch` для векторов).
*   **AC-3 (Retrieval):** WHEN Генератор Событий формирует промпт, THE system SHALL использовать ГИБРИДНЫЙ подход:
    *   Если у сцены есть привязанный шаблон с узлами: использовать General (Корень + L1) + Specific (топ-3 по pgvector).
    *   Если узлов нет (или шаблон не привязан): использовать сырой текст `environment_details` (fallback).
*   **AC-4 (UI - Мастерская):** В Мастерской (вкладка «Локации») есть кнопка парсинга и дерево для просмотра/удаления ошибочных узлов (ручное добавление не требуется, только текст -> LLM -> дерево).
*   **AC-5 (Консистентность):** Сцена просто хранит `chronicle_location_id`. Применение шаблона не копирует узлы, а просто ссылается на них.

## 3. Out of Scope
*   Автоматическая синхронизация текста сцены (в чате) с графом (если мастер меняет текст в чате, граф не обновляется).
*   Визуальный Drag-and-Drop редактор деревьев.

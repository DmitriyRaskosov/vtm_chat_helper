# Spec: Боевая Секвенция (Этап 3: Синхронизация и Логи)

**Status:** Completed
**Date:** 2026-11-09

## 1. Контекст и Цель

Ядро и UI трекера готовы, но сейчас они работают изолированно. Игрокам приходится обновлять страницу или ждать поллинга, чтобы увидеть изменения. Кроме того, броски кубов во время боя смешиваются с обычными бросками сцены в общем логе, а механизм передачи хода «ВАШ ХОД» не синхронизирован с трекером инициативы.

Цель — связать трекер с существующей механикой сцены и логом бросков, а также внедрить WebSockets (Reverb) для мгновенного обновления интерфейса у всех участников без перезагрузки страницы.

## 2. User Stories

*   **US-1:** Как игрок, я хочу мгновенно видеть, когда наступает мой ход в трекере, без необходимости обновлять страницу.
*   **US-2:** Как игрок, я хочу получать звуковой/визуальный сигнал, когда рассказчик передает мне ход.
*   **US-3:** Как рассказчик, я хочу, чтобы при переключении хода в трекере индикатор «ВАШ ХОД» на сцене обновлялся автоматически.
*   **US-4:** Как рассказчик, я хочу, чтобы в логе боя отображались только те броски, которые были сделаны в рамках текущего боя.
*   **US-5:** Как игрок, я хочу, чтобы броски, сделанные до боя, не смешивались с боевыми.
*   **US-6:** Как система, я хочу сохранять связь между дневником персонажа и боевой секвенцией для будущей генерации памяти.

## 3. Acceptance Criteria (EARS)

*   **AC-1 (Авто-ход):** WHEN рассказчик в трекере запрашивает следующий ход, THE system SHALL автоматически обновлять идентификатор активного персонажа сцены (индикатор «ВАШ ХОД»).
*   **AC-2 (Завершение):** WHEN бой завершается, THE system SHALL сбрасывать идентификатор активного персонажа сцены.
*   **AC-3 (Связь бросков):** WHEN происходит бросок кубов, THE system SHALL проверять наличие активной боевой секвенции. IF секвенция активна, THE system SHALL сохранять бросок с привязкой к этой секвенции.
*   **AC-4 (Фильтрация лога):** THE system SHALL отображать в панели «Лог боя» только броски, принадлежащие активной секвенции (с возможностью переключить на общий лог).
*   **AC-5 (Синхронизация старта):** WHEN бой создается, THE system SHALL транслировать событие старта всем участникам хроники.
*   **AC-6 (Синхронизация хода):** WHEN в трекере меняется активный участник, THE system SHALL транслировать событие смены хода всем участникам хроники.
*   **AC-7 (Синхронизация изменений):** WHEN меняется статус, видимость или инициатива участника, THE system SHALL транслировать событие обновления всем участникам хроники.
*   **AC-8 (Реакция клиента):** WHEN клиент получает событие синхронизации, THE system SHALL обновлять состояние трекера в реальном времени.
*   **AC-9 (Запись в дневник):** THE system SHALL сохранять идентификатор боевой секвенции в записях дневника персонажей (для последующей суммаризации).

## 4. Out of Scope

*   Логика генерации записей L0/L1 для дневника во время и после боя (Этап 4).
*   Отображение инициативы и логов в виде боевой карты.
*   Автоматическое создание бросков.

## 5. Post-Implementation Notes

Ход сцены (`game_sessions.active_character_id`) обновляется из трекера через существующий `GameSessionService`: персонаж игрока получает ход, ход NPC обнуляет индикатор. Ручная передача хода не менялась; повторное завершение уже закрытого боя ход не сбрасывает.

События `CombatStarted`, `CombatTurnChanged` и `CombatParticipantUpdated` уходят в `private-chronicle.{id}` через `ShouldBroadcastNow` и `SafeBroadcaster`, без очереди. Добавление участника тоже шлёт обновление. Бросок во время активного боя сохраняет `combat_encounter_id`; то же поле есть в ответе лога. У дневника колонка есть, генерация записей не делалась.

Пока сокет жив, трекер не опрашивается. `useCombatTracker` слушает `window.Echo.private('chronicle.{id}')`: старт перезагружает бой и открывает окно, смена хода двигает индекс и индикатор «ВАШ ХОД», изменение участника перезапрашивает трекер. Если сокет отвалился, общий запасной опрос раз в 3 секунды подтягивает сообщения, лог и боевую секвенцию. В «Логе боя» при активном бое по умолчанию видны только его броски, переключатель возвращает общий лог.

Полный PHP-сьют, Pint, PHPStan, `npm test` и `npm run build` зелёные. Два окна в браузере не прогонялись: инструментов браузера в сессии нет.

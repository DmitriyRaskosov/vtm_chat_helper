# Spec: Боевая Секвенция Сцены (Этап 1: Ядро)

**Status:** Completed
**Date:** 2026-11-09

## 1. Контекст и Цель

Сейчас боевые действия ведутся хаотично: броски, реплики и ходы смешаны в
общем чате. Рассказчик не может явно показать игрокам, кто участвует в бою,
чей сейчас ход и сколько раундов длится столкновение.

Цель — создать ядро боевой секвенции: сущность уровня сцены, которая выделяет
конкретных участников боя, автоматически рассчитывает их инициативу с учётом
чарлиста и штрафа от ранений, и позволяет рассказчику управлять очередью
ходов только вперёд. Никаких случайных бросков при расчёте инициативы:
система работает с тем, что уже записано в чарлистах.

Ядро живёт параллельно чату, логу боя и дневнику NPC. Связывание секвенции
с этими подсистемами — задача следующих этапов.

## 2. User Stories
*   **US-1:** Как рассказчик, я хочу запустить боевую секвенцию, чтобы отделить бой
  от остальной сцены.
*   **US-2:** Как рассказчик, я хочу добавить в бой только выбранных персонажей
  сцены, чтобы наблюдатели не участвовали в очередности ходов.
*   **US-3:** Как рассказчик, я хочу указать конкретные характеристики для расчёта
  инициативы (по умолчанию — Ловкость + Смекалка; override — любые ключи из
  чарлиста).
*   **US-4:** Как рассказчик, я хочу, чтобы система сама считала инициативу с учётом
  постоянных и временных точек и штрафа от ранений, без случайного броска.
*   **US-5:** Как рассказчик, я хочу скрыть некоторых участников от игроков (засада),
  не теряя их места в очереди.
*   **US-6:** Как рассказчик, я хочу переключать ходы только вперёд, с пропуском
  выбывших, чтобы вести раунды без ручной арифметики.
*   **US-7:** Как рассказчик, я хочу помечать участника выбывшим и возвращать его
  в бой, не удаляя из секвенции.
*   **US-8:** Как рассказчик, я хочу явно завершить бой, вернувшись к обычной сцене.
*   **US-9:** Как рассказчик, я хочу, чтобы активная секвенция автоматически
  завершалась при закрытии сцены.
*   **US-10:** Как игрок, я хочу видеть трекер инициативы, где скрытые участники не
  раскрываются, но их позиция в очереди сохраняется.
*   **US-11:** Как рассказчик, я хочу вручную пересчитать инициативу всех участников
  одним действием (например, при смене условий или по home rules).

## 3. Acceptance Criteria
*   **AC-1:** (Создание): WHEN рассказчик инициирует боевую секвенцию, THE system
  SHALL создать активную секвенцию с первым раундом и нулевым индексом хода.
  IF на сцене уже есть активная секвенция, THE system SHALL вернуть
  существующую без создания второй.

*   **AC-2:** (Добавление участника): WHEN рассказчик добавляет персонажа сцены,
  THE system SHALL добавить его как активного и видимого, с нерассчитанной
  инициативой. IF персонаж уже в секвенции, THE system SHALL вернуть ошибку.
  IF персонаж не участвует в сцене, THE system SHALL вернуть ошибку.

*   **AC-3:** (Настройка характеристик): WHEN рассказчик запрашивает расчёт
  инициативы, THE system SHALL принимать опциональный список ключей
  характеристик. IF список не передан, THE system SHALL использовать
  стандартную для V20 пару.

*   **AC-4:** (Расчёт инициативы): WHEN происходит расчёт инициативы, THE system
  SHALL для каждого участника сложить значения указанных характеристик,
  учитывая постоянные и временные точки, и прибавить штраф от ранений
  (штраф отрицательный). Результат SHALL сохраняться как инициатива
  участника. Никакого случайного броска система не делает.

*   **AC-5:** (Сортировка): THE system SHALL сортировать участников по убыванию
  инициативы. IF инициативы равны, THE system SHALL сортировать по значению
  первой характеристики из переданного списка. IF участник выбыл,
  THE system SHALL помещать его в конец очереди. IF инициатива не рассчитана
  (участник добавлен до первого расчёта), THE system SHALL сохранять порядок
  добавления.

*   **AC-6:** (Видимость — storyteller): WHEN рассказчик запрашивает состояние
  секвенции, THE system SHALL включать всех участников, включая скрытых.

*   **AC-7:** (Видимость — игрок): WHEN игрок запрашивает состояние секвенции,
  THE system SHALL заменять скрытых участников на обезличенную заглушку
  без имени, аватара и идентификатора персонажа, сохраняя их позицию
  в очереди и инициативу.

*   **AC-8:** (Следующий ход): WHEN рассказчик запрашивает следующий ход,
  THE system SHALL сдвигать индекс на следующего активного участника.
  IF текущий — последний активный, THE system SHALL увеличить номер раунда
  и вернуть индекс к первому активному.
  IF в секвенции нет активных участников, THE system SHALL возвращать
  ошибку. Никакого автоматического пересчёта инициативы при смене раунда
  не происходит.

*   **AC-9:** (Выбывание/возврат): WHEN рассказчик помечает участника выбывшим,
  THE system SHALL снимать с него флаг активности; при следующем
  переключении хода такой участник пропускается.
  WHEN рассказчик возвращает участника в бой, THE system SHALL ставить
  его обратно в очередь согласно его инициативе.

*   **AC-10:** (Раскрытие): WHEN рассказчик раскрывает скрытого участника,
  THE system SHALL делать его видимым для всех участников хроники.

*   **AC-11:** (Ручная правка инициативы): WHEN рассказчик меняет инициативу
  участника, THE system SHALL сохранять новое значение и пересортировывать
  очередь.

*   **AC-12:** (Завершение): WHEN рассказчик завершает секвенцию, THE system
  SHALL помечать её завершённой. После завершения storyteller и игроки
  получают обычную сцену без активной секвенции.

*   **AC-13:** (Закрытие сцены): WHEN сцена закрывается, THE system SHALL
  автоматически завершать активную секвенцию этой сцены.

*   **AC-14:** (Покидание сцены): WHEN участник покидает сцену, THE system SHALL
  помечать его в активной секвенции как выбывшего.

*   **AC-15:** (Пересчёт инициативы): WHEN рассказчик запрашивает пересчёт
  инициативы, THE system SHALL применить AC-4 ко всем участникам секвенции,
  включая уже имеющих инициативу, и сбросить очередь ходов к началу.

## 4. Out of Scope

* UI трекера инициативы и drag-and-drop — Этап 2.
* Синхронизация через WebSockets — Этап 3.
* Автоматическое проставление `active_character_id` сцены из секвенции
  (существующий механизм «ВАШ ХОД» продолжает работать независимо) — Этап 3.
* Связь секвенции с чатом, логом бросков и дневником NPC: броски, сообщения
  и L0/L1 продолжают жить в своих таблицах, секвенция параллельна им.
  Влияние боя на генерацию дневников NPC — отдельная задача вне этого
  этапа (требует самостоятельного проектирования).
* Автоматический пересчёт инициативы в начале нового раунда (см. AC-8:
  storyteller вызывает пересчёт вручную через AC-15).
* Автоматическая фильтрация лога бросков по текущему бою — Этап 3.
* Жёсткое удаление секвенции через API. Ошибочно созданная секвенция
  завершается как обычная (AC-12).
* Боевые карты, токены и позиции.

## 5. Post-Implementation Notes

Секвенция живёт отдельно от чата, бросков и дневника. Закрытие сцены завершает активный бой в `SceneLifecycleService::close` после транзакции и до `scheduleSummary()`: контроллер по-прежнему только делегирует. Уход со сцены снимает активность участника в `SceneParticipantService`.

Инициатива считается через `CharacterStatsService::filledDots()` и `legacyState()['health_penalty']`. Очередь строит чистая `sortByInitiative` без запросов к базе. Смена активности и ручная инициатива идут через идемпотентный `setParticipantActive` (`PATCH .../active`) и `setInitiative`; `reindexCurrentTurn` удерживает ход на том же `character_id`. Пересчёт `rollInitiative` сознательно сбрасывает раунд и индекс в начало.

Ответ API собирает `CombatController::serializeFor`, по тому же принципу, что скрытые броски в `DiceRollController`. Игрок видит заглушку скрытого участника: позиция и инициатива есть, `id`, `character_id`, имя и аватар нет.

Сейчас бой не пишет `active_character_id` сцены: «ВАШ ХОД» работает как раньше. Нет WebSocket-синхронизации, UI трекера и влияния боя на L0/L1. Это отдельные следующие этапы.

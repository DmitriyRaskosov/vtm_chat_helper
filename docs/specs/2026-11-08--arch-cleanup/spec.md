# Spec: Оптимизация запросов и унификация API

**Status:** Completed
**Date:** 2026-11-08

## 1. Контекст и Цель
В проекте накопился технический долг. Во-первых, проверки членства в хронике (через `chronicle_members`) выполняются в БД многократно в рамках одного запроса (например, при сборке контекста Copilot). Во-вторых, `CurrentChronicle` содержит fallback, который может маскировать ошибки роутинга. В-третьих, коды ответов API размыты: доступ к чужим данным иногда возвращает 403 (Forbidden), хотя должен возвращать 404 (Not Found), чтобы скрыть существование ресурса.
Цель — устранить эти архитектурные шероховатости.

## 2. User Stories
*   **US-1:** Как система, я хочу кэшировать проверки членства в рамках одного запроса, чтобы не нагружать БД лишними SELECT-ами.
*   **US-2:** Как система, я хочу быть уверенной в строгом Route Model Binding, чтобы избежать случайных ошибок при работе с хрониками.
*   **US-3:** Как система, я хочу возвращать 404 для всех запросов к чужим хроникам, чтобы защититься от перебора ID и скрыть структуру данных.

## 3. Acceptance Criteria (EARS)
*   **AC-1 (404 для чужих):** WHEN пользователь запрашивает ресурс (сцену, персонажа, сообщение) из хроники, в которой он не состоит, THE system SHALL возвращать 404 Not Found.
*   **AC-2 (403 для своих):** WHEN пользователь пытается выполнить запрещенное действие (например, игрок удаляет чужое сообщение) в СВОЕЙ хронике, THE system SHALL возвращать 403 Forbidden.
*   **AC-3 (Кэширование):** THE system SHALL использовать хелпер `once()` для всех проверок `isStorytellerIn()` и `ChronicleMember` в рамках одного запроса.
*   **AC-4 (CurrentChronicle):** WHEN формируется контекст, THE system SHALL получать Chronicle только из Route Model Binding. IF модель не найдена, THE system SHALL возвращать 404.

## 4. Out of Scope
*   Оптимизация запросов к БД вне контекста `chronicle_members`.

## 5. Post-Implementation Notes

Внедрено кэширование проверок членства через хелпер `once()` (снижена нагрузка на БД).

Убран fallback в `CurrentChronicle`, добавлен явный `Route::bind('chronicle')` в `bootstrap/app.php`.

Для чужих хроник теперь возвращается 404 (`ChronicleAccessDeniedException`), для нехватки прав внутри своей — 403. Это разделение реализовано через трейт `GuardsChronicleMembership`.

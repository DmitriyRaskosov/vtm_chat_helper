Структура проекта game-chat (Laravel 13 + Sail)
================================================

Mailpit в Docker оставляем как есть и не используем.

Это свежий каркас: чата, агента и своих моделей ещё нет.
Есть только заготовка плюс модель User.


КОРЕНЬ
------
Точка входа в репозиторий, не «логика игры».

composer.json / composer.lock  — список PHP-пакетов и зафиксированные версии
compose.yaml                   — Docker: PHP, PostgreSQL, Redis, Mailpit
sail.cmd                       — обёртка Sail под Windows
.env                           — секреты и порты этой машины (не в git)
.env.example                   — шаблон без секретов
artisan                        — CLI Laravel (migrate, make:…). Запускать через Sail
phpunit.xml                    — настройки тестов
README.md                      — как поднять Docker
public/                        — единственная папка, которую видит браузер


app — ваш код приложения
------------------------
Здесь будут контроллеры чата, модели партии, позже агент. Сейчас почти пусто.

Контроллер — класс, который принимает HTTP-запрос («открыли /», «отправили
сообщение») и решает, что вернуть: HTML, JSON, редирект. Маршруты Laravel
читает в routes/, а работу делает контроллер.

Модель — PHP-класс про одну сущность в БД: строка таблицы ↔ объект.
User — пользователь. Позже: Conversation, Message, GameState.
Это не «файл БД», а способ читать и писать таблицы из кода.

Провайдер — место «при старте приложения подключи вот это»: биндинги,
макросы, регистрация сервисов. Не страница сайта.

Сейчас внутри:

  Http/Controllers/Controller.php  — пустой базовый класс. Свои контроллеры
                                     будут наследоваться от него.
  Models/User.php                  — пользователь: имя, email, пароль;
                                     нужен для входа, когда подключим auth.
  Providers/AppServiceProvider.php — пустая заготовка; почти всё в Laravel 11+
                                     живёт в bootstrap/app.php.

Папок Http/Middleware, Jobs, Ai ещё нет — появятся, когда понадобятся.


bootstrap — запуск фреймворка
-----------------------------
Не «ваш сайт», а как Laravel собирается при каждом запросе.

  app.php       — маршруты (web.php, artisan, /up), middleware,
                  как отдавать JSON при ошибках.
  providers.php — список провайдеров (AppServiceProvider).
  cache/        — сгенерированные services.php, packages.php.
                  Не править руками. Это кэш, не логика игры.


config — настройки без кода фич
-------------------------------
PHP-массивы: что читать из .env. Меняете поведение (драйвер БД, почта,
очередь), не страницы.

  app.php          — имя / окружение
  database.php     — PostgreSQL
  queue.php        — очереди (потом для агента)
  mail.php         — почта (Mailpit в Docker, мы не используем)
  auth.php
  session.php
  cache.php
  filesystems.php
  logging.php
  services.php


database — схема и тестовые данные
----------------------------------
Не «база», а как её создать и наполнить. Живые данные — в PostgreSQL в Docker.

  migrations/              — пошаговые изменения таблиц.
                             Сейчас: users (+ password_reset_tokens, sessions),
                             cache, jobs (очередь).
  factories/UserFactory.php — фейковые пользователи для тестов.
  seeders/DatabaseSeeder.php — «залить демо-данные»; сейчас почти пустой.


routes — карта URL и команд
---------------------------
«Какой адрес → какая функция».

  web.php     — браузер. Сейчас один маршрут: / → view welcome
                (приветствие Laravel).
  console.php — свои artisan-команды по расписанию; заготовка.

API-файла нет; в bootstrap/app.php уже заложено, что /api/* может
отвечать JSON.


resources — то, что видит человек (и фронт)
------------------------------------------
  views/welcome.blade.php — HTML стартовой страницы (шаблон Blade).
  css/app.css, js/app.js  — заготовки стилей и JS.

Чат UI позже будет здесь (views + js), не в vendor.


public — вход с интернета
-------------------------
Nginx/Sail отдаёт только это.

  index.php   — каждый HTTP-запрос начинается здесь, дальше Laravel.
  .htaccess   — Apache (у нас Docker/Sail, почти не важно).
  robots.txt  — для поисковиков.

Картинки и собранный фронт тоже кладут сюда.
Не класть сюда .env и app/.


storage — файлы, которые пишет приложение
-----------------------------------------
Логи, сессии, кэш скомпилированных Blade, загрузки. Не исходники.

  storage/logs           — смотреть ошибки
  framework/views        — кэш шаблонов (не править)


tests — автопроверки
--------------------
  TestCase.php              — база для тестов.
  Feature/ExampleTest.php   — «сайт отвечает 200 на /».
  Unit/ExampleTest.php      — заглушка.

Позже: «сообщение сохранилось», «агент вызвался».


vendor — чужой код
------------------
То, что поставил Composer: Laravel, Sail, Symfony, PHPUnit.
Не редактировать. Тысячи файлов — норма.


Как это склеивается на один запрос
----------------------------------
Браузер
  → public/index.php
  → bootstrap/app.php
  → routes/web.php  (маршрут /)
  → сейчас сразу view('welcome') без своего контроллера
  → resources/views/welcome.blade.php

Модели и БД на главной ещё не участвуют.

Когда появится чат:
  маршрут в routes/web.php
  → контроллер в app/Http/Controllers
  → модели в app/Models
  → таблицы из database/migrations
  → ответ view или JSON.
